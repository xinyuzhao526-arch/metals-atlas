# 数据口径

本平台不把缺失值解释为零。数据库和 API 使用 `null` 并附带 `missing_reason`；中文“待补”仅是前端展示。

自然年与公司财年分别记录。财年记录必须保存财年标签和财年起始月；季度、YTD 和年度值不自动互相推导。项目 100% 总量、权益、应占和合并口径分别记录，不自动混合。生产环节必须显式保存，不跨矿端含金属、精矿含金属、阴极铜或冶炼产出求和。

每个数值引用一份具体材料，并保存材料发布日期、观察有效日期、核验日期和材料内定位。任何人工修改都在 Phase 1A 审核项中保留修改前后快照。Phase 1A 的“接受并发布”会立即公开，这是临时产品语义。

Phase 1B.1 的研究候选与公开观察记录严格分离。Extractor 只能创建候选，候选经过单位、期间、生产环节、所有权口径和证据完整性校验后，仍须由管理员执行一次“确认并发布”或“修改并发布”。`needs_attention` 不能直接发布；`NULL` 不得转换为 0。

来源等级 A 表示矿企官网、正式公告、交易所/监管披露或政府机构等公开一手资料；搜索结果和摘要只能用于发现，不能直接作为事实依据。每条公开研究数据必须保留官方链接、发布机构、标题、发布日期、有效日期、原始值与单位、标准化值与单位、期间口径、生产环节、所有权口径、具体证据定位、摘录、提取方式和管理员确认时间。

首条真实试点为 Kansanshi：First Quantum 2025 Q4 铜产量 47,655 tonnes，标准化为 47.655 kt；来源为 First Quantum 正式第四季度业绩公告，按含铜量、进入 Kansanshi 冶炼厂处理之前的口径记录，所有权字段保存为 `consolidated`。该候选由窄规则确定性提取器发现，`extraction_method=deterministic`，经管理员确认后发布。

当前没有配置或调用在线模型 API。Phase 1B.2 才会选择具体模型供应商、独立 API 凭据、版本化提示词、评估样本和官方域名自动发现；ChatGPT/Codex 订阅不能作为网站调用模型的凭据。

演示工作簿中的数字是合成 fixture，不是已核验生产事实。`example.invalid` 链接、`demo_fixture` 类型和 `is_demo=true` 用于防止误用。
