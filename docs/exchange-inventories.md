# 交易所库存覆盖

铜使用 `apps/web/data/inventories.json`；锂、镍、铝使用 `apps/web/data/metal-inventories.json`，后者按金属、交易所、定义隔离，来源材料单独存放在 `sources`。

| 金属 / 产品 | 交易所 | 序列 | 来源 |
| --- | --- | --- | --- |
| 碳酸锂 | GFEX | 注册仓单日报 | 广期所公开接口；只读 lc 小计并与逐仓库合计核对 |
| 精炼镍、原铝 | SHFE | 库存周报、仓单日报 | 上期所公开 HTML 报告，分别选取对应产品总计 |
| 精炼镍、原铝 | LME | 总库存快照 | Westmetall 公开库存表（B 级）；最新快照保留 The Vault Report 作为后备来源 |

碳酸锂原始仓单单位为手，按 1 吨/手折算产品吨；不换算成锂金属、锂辉石精矿或其他锂化学品吨位。LME 历史表取第 4 列库存吨位，不采集价格；历史表的相邻报告日变化与后备快照的 30 日变化分开标明。优先保留精确到吨的表格数值，后备快照不得覆盖同日更高精度记录。旧快照来源材料元数据仍保留。

每条观察记录保存 `source_code`、`record_key`、金属、生产阶段、有效日期、发布日期、核验日期和具体来源材料 ID。报告日期未验证、合计不符、字段缺失时拒绝写入数值；保留上次观察值并显示更新失败状态。不会把缺失值转换为零，不补造历史序列。

在 `apps/web` 中执行 `node scripts/refresh-all-inventories.mjs` 可更新全部已接入的金属；现有 GitHub Actions 库存工作流在工作日北京时间 18:17 执行。各来源独立尝试，全部来源失败时命令失败。无新数据时不重复提交。同一来源、定义和报告日期采用稳定 ID 覆写，不重复新增。

验证执行 `npm run test:unit`、`npm run typecheck`、`npm run build:pages`。测试只使用固定夹具和仓库快照，不访问网络。

## 历史回填

在 `apps/web` 中执行：

```powershell
npm run backfill:inventories -- 2026-07-20 2026-10-20
```

不传日期时默认回填最近三个月。广期所和上期所最多两个请求并行、逐份报告限速；重复运行按稳定键去重并跳过已存在的完整报告。失败报告重试一次，仍失败则记录原因、保留已核验数据并返回失败状态。周末不请求，节假日无报告明确记录，不补零或插值。LME 仅保留指定区间的公开转载库存事实和来源定位，不保存原网页或价格列。

回填区间、各序列数量、起止日期、无报告日期及失败报告写入 `metal-inventories.json` 的 `history`，不改变报告发布日期或当前核验日期。页面展示实际序列范围，镍、铝默认选中上期所周库存，LME 历史位于独立交易所页签。
